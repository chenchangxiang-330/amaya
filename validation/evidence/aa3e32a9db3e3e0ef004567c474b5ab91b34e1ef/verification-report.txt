Behavior
Successful local write_file/edit_file results referencing an absolute .html/.htm file produce a preview below the assistant message, outside collapsed tool/work groups. Duplicate paths within the message are shown once. The host-resolved write_file output also supports originally relative tool arguments. English and Simplified Chinese UI strings are provided.
Local HTML runs in Android WebView, including JavaScript, standard alert/confirm/prompt dialogs, buttons, CSS, local images and same-directory/subdirectory web assets. Expand resizes the existing WebView; Refresh reloads current disk contents. No native JavaScript bridge or file/content URL access is exposed. Each instance uses a separate random virtual HTTPS origin. Assets are bounded to the HTML parent directory by canonical path checks, supported extensions and an 8 MiB limit per file. Network loads are disabled and a restrictive CSP is supplied.

Limitations / not verified
No real DeepSeek or third-party model response was used; no API credentials were accessed.
Only successful local HTML write/edit tool records are auto-detected. Bare file paths in prose, fenced HTML code blocks, files created solely by shell commands and remote-workspace files are not auto-previewed.
CDN assets, online APIs, server-dependent sites, forms requiring server submission and pop-up windows are unsupported. DOM local storage is disabled. Use self-contained HTML or local assets. This does not provide a backend server.
Preview reflects the file currently on disk, not an immutable snapshot of the old message. Deleted/unreadable/oversized files show an unavailable message. A refresh is needed after later asset edits. Form/JavaScript state is preserved during expand/collapse, but not promised across reload, scrolling offscreen, navigation or process restart.
Visual review: Chinese and English inline previews, expanded view, refresh, native alert and post-restart screenshots were inspected. At the tested default font size, Chinese buttons and footer text were visible without overlap; expansion creates a taller preview region inside the chat. Ten final screenshots are retained across api-30 and api-33.
The dedicated HTML runtime fixture is narrower than a full real-model project workflow. Standard JavaScript dialogs use WebView's built-in title, which includes the internal virtual origin. Only alert was runtime-tested; confirm/prompt use the same default WebChromeClient behavior.
Large-font rendering, accessibility screen-reader operation, arbitrary generated sites and the user's actual handset have not been runtime-tested for this feature.
